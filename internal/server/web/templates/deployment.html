Enrollment

agents present this token once, then use their own identity
{{.ServerURL}}
{{.EnrollToken}}
{{.Interval}} seconds
agents replace themselves when this server serves a different build

Agents compare the digest of their own binary with the one this server would send them, so an update happens exactly once and cannot loop. A replacement is downloaded, checksum-verified, and run before it is installed — a binary that cannot execute is discarded rather than bricking the machine. Updates are never offered while a device has work outstanding.

Rotating the token blocks new enrollments with the old value. Devices already enrolled keep working — they authenticate with a per-device token issued at enrollment, not with this one.

Install

run in the foreground first to confirm check-in, then install as a service

Recommended — one line

curl -fsSL "{{.ServerURL}}/install.sh?token={{.EnrollToken}}" | sudo sh

Detects whether the machine is amd64 or arm64, downloads the matching build, installs to /usr/local/bin, and registers a systemd service. Add --no-service to skip the service, or --prefix DIR to install elsewhere. Pipe to sh -s -- --no-service to pass flags through the pipe.

Manual — 1. download and run

arch=$(uname -m); case $arch in x86_64) arch=amd64 ;; aarch64) arch=arm64 ;; esac
curl -fsSL -o monitorrr-agent "{{.ServerURL}}/download/monitorrr-agent-linux-$arch?token={{.EnrollToken}}"
chmod +x monitorrr-agent
sudo ./monitorrr-agent -server {{.ServerURL}} -enroll-token {{.EnrollToken}}

The uname -m line matters: an Ubuntu VM on an Apple Silicon host is arm64, and running an amd64 binary there fails with cannot execute binary file.

Manual — 2. install as a systemd service

sudo install -m 0755 monitorrr-agent /usr/local/bin/monitorrr-agent
sudo tee /etc/systemd/system/monitorrr-agent.service >/dev/null <<'EOF'
[Unit]
Description=monitorrr agent
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/monitorrr-agent -server {{.ServerURL}} -enroll-token {{.EnrollToken}}
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now monitorrr-agent
systemctl status monitorrr-agent

Recommended — one line

curl -fsSL "{{.ServerURL}}/install.sh?token={{.EnrollToken}}" | sudo sh

Same installer as Linux: it picks Apple Silicon or Intel automatically, clears the Gatekeeper quarantine flag, and registers a launchd daemon.

Manual — 1. download and run

arch=$(uname -m)  # arm64 on Apple Silicon, x86_64 → amd64 on Intel
[ "$arch" = "x86_64" ] && arch=amd64
curl -fsSL -o monitorrr-agent "{{.ServerURL}}/download/monitorrr-agent-darwin-$arch?token={{.EnrollToken}}"
chmod +x monitorrr-agent
xattr -d com.apple.quarantine monitorrr-agent 2>/dev/null || true
sudo ./monitorrr-agent -server {{.ServerURL}} -enroll-token {{.EnrollToken}}

The xattr line clears Gatekeeper's quarantine flag on an unsigned binary fetched over the network.

Manual — 2. install as a launchd daemon

sudo install -m 0755 monitorrr-agent /usr/local/bin/monitorrr-agent
sudo tee /Library/LaunchDaemons/io.monitorrr.agent.plist >/dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>io.monitorrr.agent</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/local/bin/monitorrr-agent</string>
    <string>-server</string><string>{{.ServerURL}}</string>
    <string>-enroll-token</string><string>{{.EnrollToken}}</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict>
</plist>
EOF
sudo launchctl load -w /Library/LaunchDaemons/io.monitorrr.agent.plist

1. Download and run

$arch = if ($env:PROCESSOR_ARCHITECTURE -eq "ARM64") { "arm64" } else { "amd64" }
Invoke-WebRequest -Uri "{{.ServerURL}}/download/monitorrr-agent-windows-$arch.exe?token={{.EnrollToken}}" -OutFile "monitorrr-agent.exe"
.\monitorrr-agent.exe -server {{.ServerURL}} -enroll-token {{.EnrollToken}}

The $arch line matters on Windows-on-ARM VMs. SmartScreen may warn on an unsigned binary. Run PowerShell as Administrator so the agent can write its identity to C:\ProgramData\monitorrr.

2. Install as a scheduled task at boot

New-Item -ItemType Directory -Force -Path "C:\Program Files\monitorrr" | Out-Null
Copy-Item .\monitorrr-agent.exe "C:\Program Files\monitorrr\monitorrr-agent.exe" -Force

$action  = New-ScheduledTaskAction -Execute "C:\Program Files\monitorrr\monitorrr-agent.exe" `
             -Argument '-server {{.ServerURL}} -enroll-token {{.EnrollToken}}'
$trigger = New-ScheduledTaskTrigger -AtStartup
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest
$settings = New-ScheduledTaskSettingsSet -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask -TaskName "monitorrr-agent" -Action $action -Trigger $trigger `
  -Principal $principal -Settings $settings -Force
Start-ScheduledTask -TaskName "monitorrr-agent"

A scheduled task avoids pulling in a Windows service wrapper dependency. Swap it for a real service later if you want sc.exe control.
